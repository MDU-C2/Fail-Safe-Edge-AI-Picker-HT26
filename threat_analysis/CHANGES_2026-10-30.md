## Threat changes

70 threats (previously 51): 10 critical, 28 high, 24 medium, 8 low, none TBD. **5 Mitigated, 65 Open.**

- Old numbers 1–51 are kept where the threat still applies, so existing references stay valid. New threats are numbered 52–79.
- Removed: 25 and 26 (Pi flow duplicates of 46) and 44 (merged into 43 and 42). Since all RGB-D now passes through one camera → gateway flow, threats 6, 29 and 30 appear once instead of three times.
- All descriptions and mitigations were rewritten against the code. Each mitigation now begins with **Implemented:** (what the code does) and/or **Remaining:**/**Planned:** (what is missing). Text is in British English.
- **Mitigated** is only used where the code implements the control and a test checks it:
  - 30, stale camera image (503 after 5 s, reconnect)
  - 68, token hash reversal (256-bit random tokens)
  - 71, unauthenticated client (strict mode, `test_auth.py`)
  - 72, read-only client acting (403/409)
  - 73, conflicting jobs (lease, per-arm 409, `test_control.py`)
- New **spoofing** threats:
  - 52, stolen or shared token over plain HTTP. The inference script uses the operator token.
  - 59, spoofed camera address.
  - 71, as above.
  - 11 is now "direct robot commands bypassing the gateway" (default RWS account, unauthenticated CommServer).
- New **repudiation** threats: 53 (no audit log in the gateway), 60 (all RWS traffic uses one account) and 63 (shared operator identity).
- Other new threats found in the code:
  - 54, arbitrary RAPID upload through the gateway by any control client. Critical.
  - 55, the legacy route skips the safe zone.
  - 56, a lapsed lease leaves the robot moving (`TODO.md`).
  - 57, development mode.
  - 58, no rate limiting.
  - 64, unsigned and unpinned image.
  - 65, secrets baked into the image.
  - 62, tampered calibration.
  - 42, now notes that a `.pt` file is a pickle and can run code when loaded.
  - 45, Pi heat (86 °C).
  - 50, Lynx stops in live mode.
  - 79, `rapidctl.py` changes RAPID outside the gateway.

## Severity changes the group should confirm

- 11 High → Critical: it is now the gateway-bypass threat.
- 17 TBD → High.
- 39 TBD → Low: the MacBook stands in for the cloud.
- 7 Medium → Low: the Pi client and the gateway are on the same host.
- 23 Medium → High: it now includes token exposure.
- 27 Low → Medium: same reason as 23.

New threats were rated as follows. Critical means it can directly cause unsafe robot motion and needs only network access. High means unsafe motion with an extra precondition, or loss of credentials or of the whole system. Medium means degraded operation, or disclosure that helps an attacker. Low means minor. **This rubric was applied by Claude, not agreed by the group.**
